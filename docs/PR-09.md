# PR-09 — Safe Windows Cleanup Pack

PR-09 prioritizes **scope correctness and supported Windows behavior** before expanding the number of destructive cleanup categories.

The governing rule is:

> The scope Purgio estimates, shows in the Cleanup Plan, and authorizes for deletion must describe the same data.

No cleanup category is considered “safe” merely because other cleaner utilities delete it.

## Windows scanner hardening

`get_dir_size` now uses `symlink_metadata` and mirrors the important traversal protections from the cleaner while estimating disk usage:

- critical paths are skipped;
- symbolic links are not followed;
- Windows junctions/reparse points are not followed;
- recursion remains depth-bounded to prevent an unbounded scan.

The size displayed by Purgio remains an estimate, but the scanner no longer crosses a link/reparse boundary that the cleaner itself would refuse to traverse.

## Thumbnail cache — exact file scope

The previous `win_thumb_cache` implementation counted only `thumbcache_*.db` files but authorized the whole `%LOCALAPPDATA%\Microsoft\Windows\Explorer` directory for deletion.

PR-09 fixes that mismatch:

- only actual `thumbcache_*.db` files are collected;
- entries must be regular files;
- symlinks and reparse points are excluded;
- critical paths are excluded;
- the exact file paths are sorted/deduplicated and become the authorized Cleanup Plan paths;
- the size is the sum of those same exact files.

A Windows unit test verifies the filename filter and rejects `iconcache_*`, backup suffixes, and non-matching names.

## `C:\Windows\Temp` — Review, not automatic

Direct cleanup of `C:\Windows\Temp` is no longer marked `Safe`/selected by default.

It remains available as **Review** because:

- Windows and services can actively use entries in this directory;
- permissions can vary;
- some files may be intentionally retained by the OS;
- Purgio's cleaner will still skip protected links/reparse points and report files it could not remove.

The Cleanup Plan explicitly explains this behavior before execution.

## Windows Update cache — raw deletion removed

The former `win_update_cache` target directly authorized all of:

`C:\Windows\SoftwareDistribution\Download`

as a generic Safe cleanup item.

PR-09 removes that raw directory deletion. Windows Update cleanup will only return when Purgio has a supported Windows action model that can use an appropriate OS-supported mechanism rather than treating an internal servicing directory as ordinary cache storage.

## Windows system logs — broad target removed

The former `win_logs` target authorized all of:

`C:\Windows\Logs`

as Safe. That target has been removed rather than trying to guess which diagnostic/service logs are disposable.

Future log cleanup must enumerate explicit artifacts or use a supported Windows mechanism.

## Application crash dumps — exact `.dmp` files, Review

`%LOCALAPPDATA%\CrashDumps` was previously treated as a Safe directory cleanup.

PR-09 changes `win_wer` so that it:

- enumerates only direct `.dmp` files;
- authorizes each dump file individually;
- excludes symlinks/reparse points/non-files;
- is classified **Review** and therefore is not selected automatically;
- states clearly that deleting dumps removes evidence useful for debugging previous crashes.

## Windows system memory dumps — exact files, Review

A bounded diagnostic cleanup item can recover substantial disk space without authorizing an entire system directory.

`win_error_dumps` includes only existing exact files from:

- `C:\Windows\MEMORY.DMP`
- direct `*.dmp` files in `C:\Windows\Minidump`

Each candidate must be a regular non-symlink/non-reparse file and must pass the critical-path safety check.

The category is **Review**, not automatic, because the dumps may be needed to diagnose crashes or blue screens.

## Windows Recycle Bin — unsafe raw path removed

The previous scanner authorized `C:\$Recycle.Bin` as a normal Safe path. That can span SID-specific recycle-bin containers and is not an appropriate trust boundary for a per-user cleanup application.

PR-09 removes the raw-path item entirely.

If Recycle Bin cleanup returns, it must use the Windows Shell APIs (`SHQueryRecycleBin` / `SHEmptyRecycleBin`) or an equivalent supported system-action abstraction, and the UI must clearly describe the irreversible operation.

## DirectX shader cache — researched but intentionally not added

Microsoft documents shader caches as clearable storage, but its Direct3D documentation also states that applications should not manually delete cache files stored outside their own working directory. The initial implementation considered `%LOCALAPPDATA%\D3DSCache`, then removed it during review.

Purgio will not ship a raw `D3DSCache` deletion target. A future implementation must use a supported Direct3D/Disk Cleanup mechanism.

## Downloads and cloud data

Downloads remain a **Review** item and are not selected automatically. PR-09 does not add automatic cleanup for cloud-backed content.

This follows Windows Storage Sense semantics, where Downloads and locally available cloud content have separate user-controlled policies rather than being treated as generic temporary files.

## Windows.old and Component Store

PR-09 does not recursively delete `Windows.old` or manipulate WinSxS.

- `Windows.old` should be handled using Storage Sense / Cleanup Recommendations.
- Component Store analysis/cleanup remains PR-12.
- `/ResetBase` will never be a default cleanup action because it changes update rollback/removal capability.

## Browser boundary

PR-09 intentionally does not modify the Chromium `Default\File System` download-artifact target. That target is already known to be too broad and belongs to PR-10, which will harden browser-specific cleanup separately.

## Localization

All new Windows diagnostic/system-temp/thumbnail metadata added by this PR is translated through the ES/EN presentation layer. Cleanup IDs and paths remain language-independent.

## CI

PR-09 expands the focal Rust formatting gate to include `scanner.rs` and preserves all existing gates:

- production dependency audit;
- i18n coverage and locale tests;
- TypeScript/Vite build;
- rustfmt for scanner/cleaner/safety/persistence;
- all Rust tests;
- strict crate-wide Clippy with `-D warnings`;
- NSIS branding validation;
- real Windows installer build and `*-setup.exe` verification.
