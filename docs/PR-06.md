# PR-06 — Persisted settings and migration

Purgio stores user preferences and cleanup history in `app_config_dir/state.json` through the Rust backend.

## Persisted state

- schema version
- theme
- language
- cleanup confirmation
- startup-disable confirmation
- sensitive-item visibility
- bounded cleanup history (50 entries)

## Migration

Existing `purgio-theme` and `purgio-clean-history` values are imported once from WebView localStorage. After the backend confirms the migration, the legacy keys are removed.

## Safety

State writes use a temporary file plus backup recovery. Corrupt JSON is quarantined and safe defaults are used. Unknown future schema versions are rejected rather than silently reinterpreted.

Cleanup execution and history persistence are treated as separate outcomes. If files were successfully cleaned but the history entry cannot be saved, Purgio still reports the completed cleanup and shows a separate warning about the history failure.

## Validation

`persistence.rs` is covered by the Rust formatting gate, unit tests and strict Clippy. The PR must also keep the frontend production-dependency audit/build and the real branded Windows NSIS package validation green before merge.

The strict Clippy pass identified two test-only `field_reassign_with_default` findings. They were corrected with struct update syntax; no lint suppression or relaxation of `-D warnings` was introduced. The corrected test code is now part of the final validation head.
