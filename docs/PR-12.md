# PR-12 — Windows Component Store analyzer

PR-12 integrates Windows Component Store analysis as an operating-system servicing workflow, not as ordinary filesystem deletion.

## Supported Windows boundary

Purgio never recursively deletes `C:\Windows\WinSxS` and never estimates its real size by walking files. The Component Store uses hard links and Windows servicing metadata, so DISM is the source of truth.

The backend executes only fixed commands:

- analysis: `dism.exe /Online /Cleanup-Image /AnalyzeComponentStore /English`
- standard cleanup: `dism.exe /Online /Cleanup-Image /StartComponentCleanup /English /NoRestart`

No command text, executable path, DISM switch or arbitrary shell input is supplied by the frontend.

## `/ResetBase` is excluded

Purgio does not expose `/ResetBase` in this workflow. Microsoft documents that after `StartComponentCleanup /ResetBase`, installed Windows updates can no longer be uninstalled. That changes rollback capability and is not appropriate for normal cleanup.

A Rust test permanently asserts that neither command argument list contains `/ResetBase`.

## Privilege model

Purgio does not add a generic shell plugin or silently bypass UAC. If DISM reports that elevated permissions are required, the backend returns `requires_elevation` and the UI asks the user to reopen Purgio as administrator.

This preserves the current-user default installation/runtime model instead of making every launch privileged.

## Fail-closed analysis parser

DISM is invoked with `/English` so the parser does not depend on the Windows display language. The parser requires these fields before accepting an analysis:

- Windows Explorer Reported Size of Component Store;
- Actual Size of Component Store;
- Component Store Cleanup Recommended with a strict Yes/No value.

Optional fields include shared size, backups/disabled features, cache/temporary data, last cleanup and reclaimable package count.

If mandatory fields are missing or the recommendation changes to an unknown value, parsing fails rather than inventing a recommendation.

DISM output exposed for diagnostics is bounded to 16,000 characters and NUL bytes are removed.

## Cleanup workflow

The cleanup button is shown only after a successful analysis says cleanup is recommended. The user must explicitly acknowledge that the action uses `StartComponentCleanup`, not `ResetBase`, and will not automatically restart Windows.

After a successful cleanup, Purgio immediately runs `AnalyzeComponentStore` again and reports the post-operation state rather than claiming a predicted byte count.

If cleanup succeeds but re-analysis fails, the UI receives that distinction instead of pretending the entire operation failed or inventing a result.

## UI separation

Component Store servicing is displayed as a dedicated panel on the system cleaner page. It is intentionally outside `CleanableItem`, `preview_clean_items`, `clean_items`, and the ordinary file Cleanup Plan because DISM servicing is a different trust boundary from deleting backend-authorized filesystem paths.

## Tests

The Rust module covers:

- supported field parsing;
- fail-closed behavior when the cleanup recommendation is missing;
- fail-closed behavior for unknown recommendation values;
- elevation-error detection;
- fixed-command assertions proving `/ResetBase` is absent and `/English`/`/NoRestart` are present where required.
