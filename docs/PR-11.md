# PR-11 — Chrome on-device model detector

PR-11 adds a **read-only, fail-closed detector** for Chrome's managed on-device model component and deliberately keeps it outside Purgio's generic cleanup catalog.

## Official component identity

Chromium currently defines:

- manifest name: `Optimization Guide On Device Model`
- component ID: `fklghjjljmnfjoepjmlobpekiapffcja`
- relative install directory: `OptGuideOnDeviceModel`
- management page: `chrome://on-device-internals`

The component is managed by Chrome's Component Updater.

## Why Purgio does not delete the directory directly

Chrome now exposes an **Uninstall** action in `chrome://on-device-internals`. That action reaches Chrome's own on-device model state manager and Component Updater lifecycle.

Purgio therefore does not turn the component into a `CleanableItem` and does not route it through `clean_items`.

This avoids:

- deleting files behind Chrome's state manager;
- leaving Component Updater state inconsistent;
- pretending an internal Chrome API is a public external API;
- reintroducing broad shell/opener permissions just to launch a URL.

The UI instead gives the user the exact Chrome management address and explains that Chrome may redownload the component later if the device becomes eligible and a built-in AI feature needs it.

## Detection root

The detector derives Chrome's standard User Data Directory by platform and only inspects the exact child:

`<Chrome User Data>/OptGuideOnDeviceModel`

It does not globally search the disk for folders with that name.

### Windows

`%LOCALAPPDATA%\Google\Chrome\User Data\OptGuideOnDeviceModel`

### macOS

`~/Library/Application Support/Google/Chrome/OptGuideOnDeviceModel`

### Linux

`${CHROME_CONFIG_HOME:-${XDG_CONFIG_HOME:-~/.config}}/google-chrome/OptGuideOnDeviceModel`

## Version validation

Only direct child directories with numeric dot-separated version syntax are considered candidates.

A candidate is accepted only when all of these checks pass:

1. the component root/version/files do not resolve through critical paths;
2. no target is a symlink or reparse point;
3. Windows paths do not cross a junction/reparse ancestor;
4. the version directory name parses as numeric components;
5. the version contains both files currently required by Chromium's own installation verification:
   - `weights.bin`
   - `on_device_model_execution_config.pb`
6. the verified directory has a non-zero safely measured size.

Any failure excludes the candidate rather than guessing.

## Data returned to the UI

The Tauri command `get_chrome_on_device_model_info` returns a separate structure:

- installed / not detected;
- official component name and ID;
- expected component root;
- total size of verified versions;
- each verified version, path and measured size;
- the fixed management URL `chrome://on-device-internals`.

This structure is never merged into the `CleanableItem` list.

## Browser UI

The Browsers page shows a dedicated card after a scan:

- detected/not detected status;
- verified versions;
- total size;
- component ID;
- detected root;
- explicit explanation that Purgio does not delete the component directory;
- instructions to open `chrome://on-device-internals` in Google Chrome and use **Uninstall**.

The model cannot be selected by the browser cleanup table or added to a Cleanup Plan.

## Tests

PR-11 adds tests for:

- fail-closed version syntax;
- exact Chromium component identity;
- filesystem verification requiring **both** Chromium-required model files before a version is accepted.

## CI

The focal Rust formatting gate now includes `src-tauri/src/chrome_ai.rs`. Existing production audit, i18n, frontend build, all Rust tests, strict Clippy and real Windows NSIS build/output verification remain unchanged.
